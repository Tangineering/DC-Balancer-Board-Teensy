## Derived quantities

- **`k_t` = (3/2)·p·λ = 1.5 × 2 × 1.422e-3 = 4.266e-3 N·m/A** (q-axis peak-current
  convention — the current `setCurrent()` commands). Replaces the 5.457e-3 placeholder
  (KV 1750): ×0.78, inside the `K_v ∈ {0.5, 2}` corner axis.
- **Pole-pair cross-check:** λ_predicted = 60/(√3·2π·KV·p) = 60/(√3·2π·1900·2)
  = 1.451 mWb vs 1.422 mWb measured (2.0 % off) → p = 2 confirmed; KV 1900 consistent.
- **`R_m` = 22.6 mΩ measured** (replaces the 0.075 Ω spec-can placeholder; was a 4.5 %
  sensitivity item, now exact).
- **VESC current-loop bandwidth implied by the detection gains:** VESC sets
  KP = L·α, KI = R·α. From KP: α = 0.0110/10.96e-6 = 1004 rad/s; check via KI:
  0.0226 × 1004 = 22.7 ≈ 22.60 ✓. So the FOC current loop is tuned for
  **τ ≈ 1/α ≈ 1.0 ms** — the VESC Tool default 1000 µs time constant, and exactly the
  `τ_v` design placeholder. The bench step test (below) should confirm ~1 ms.

## Td_v — DECIDED, not measured (operator decision 2026-08-15)

**Td_v = 2 ms nominal, corners {1, 4} ms retained** — the same values the checked-in
synthesis used. Rationale: the analytic decomposition bounds the true value at
~0.9–2 ms (UART frame 781 µs + VESC packet-thread processing ≲ 1 ms + FOC pickup
≤ ~70 µs), well inside the corner axis; every drive corner is gate-checked stable with
PM > 45° and delay margin > 4 ms, so measurement buys nothing unless the corners were
to be tightened for bandwidth. Direct measurement was declined to avoid placing a
current instrument in the motor power path (P3 pre-charge inrush + disconnect-under-
load hazard). Backstop: the small-signal `'V'` step validation against the design step
response would expose a delay assumption error as excess phase/overshoot.
