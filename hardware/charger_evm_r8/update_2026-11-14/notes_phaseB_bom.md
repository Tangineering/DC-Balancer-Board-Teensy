## 5. Verification

### 5.1 Schematic generator

Before the edit, `gen/sch.py` regenerated `cr/cr.kicad_sch`, `eib/eib.kicad_sch` and both symbol libraries
identically to the working tree, ignoring line endings. The regeneration therefore changes only what `gen/netlist.py`
changes. The files were written back with CRLF line endings, so the symbol libraries and `sym-lib-table` show no
change.

### 5.2 Net membership

A net-membership comparison of the old and new `cr.net` and `eib.net` (scratch script `netcmp.py`) gives identical
membership on all 76 CR and 34 EIB nets (unconnected-pin nets included), the same 78 and 46 references, and field
differences only as in Table 2. New hashes (sha256): `cr/cr.net` 39a6c659...a2ea3d, `eib/eib.net` 14ff5713...2ff2d0b.
The connectivity freeze of design r9-13 is unchanged; the frozen file hash is not (DOC-11 re-freeze, records step).

### 5.3 ERC

`kicad-cli sch erc --severity-all`: 0 errors, 0 warnings on both schematics (`cr/erc.rpt`, `eib/erc.rpt`).

### 5.4 Board fields

`gen/sync_fields.py` changed 54 CR fields and 17 EIB fields. A line diff of each board against its copy taken just
before the sync shows only `property` lines: Value, MPN, Manufacturer and Note (CR 108 lines, EIB 34 lines). The
footprints U102, U103, U119, U120 and D103 have no Note field on the board, so their new notes reach the schematic,
the netlist and the fab BOM only.

### 5.5 DRC and constraint check

`kicad-cli pcb drc --severity-all --schematic-parity`:

- Before the sync, with the new netlist: CR 0 violations, 0 unconnected, 13 parity items; EIB 0, 0, 7. All 20 parity
  items are value mismatches of the changed parts.
- After the sync: CR 0 / 0 / 0; EIB 0 / 0 / 0.

`gen/check_constraints.py`: the report after the sync is byte-identical to the report before the sync on both boards
(CR 110 pass rows, 0 FAIL).

### 5.6 Copper

`gen/pcbdiff.py` against git HEAD: CR 692 segments and 420 vias, EIB 332 segments and 93 vias, 0 removed and 0 added
on both. The zone differences against HEAD are fill-only and come from phase A. Against the pre-sync copy: 0 segment,
via and zone differences; only footprint properties differ (26 CR and 8 EIB footprints).

### 5.7 BOM regeneration

`python gen/bom_split.py bom_2026-11-14`: CR 46 rows (72 parts), EIB 13 rows (25 parts), system 26 rows, 61 Digi-Key
MPNs (62 lines), 4 Mouser lines, 35 skipped. The netlist MPN check passes with the synced netlist. Against
`bom_2026-11-13/`, the 62 main Digi-Key lines are identical in quantity, Digi-Key part number, MPN, manufacturer,
Customer Reference and designators. Only two descriptions (C102b, PLT1M-C) and the PLT1M-C price changed. The
alternate lines are new. `mouser_import.csv` and `digikey_skipped.csv` are identical in content.
